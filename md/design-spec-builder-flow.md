## 1. 섹션 해석

`70:623`은 하나의 웹 화면이 아니라 상품 만들기 과정을 구성하는 다섯 개 화면을 나란히 모아둔 Figma 섹션이다.

```text
1단계 상품 기본 정보
  → 2단계 상품 사진과 소개
  → 3단계 가게 정보
  → 상품 페이지 미리보기
  → 완성 및 DUMMY QR 표시
```

- 각 프레임의 720px 폭은 디자인 기준 크기이며 모달이 아니다.
- 실제 구현은 기존 `/builder` 독립 페이지 안에서 단계 상태에 따라 한 화면씩 교체한다.
- 아직 승인되지 않은 별도 라우트나 다섯 페이지 컴포넌트를 만들지 않는다.
- `BuilderPage.vue` 한 파일에 단계별 section을 두고, CSS는 기존 `builder.css`에서 관리한다.
- 입력값은 브라우저의 Vue 로컬 상태로만 유지하며 서버, DB, API와 연결하지 않는다.

## 2. AI UI 정책

Figma 2단계의 AI UI는 실제 AI 기능 없이 더미 화면 과정으로 구현한다.

- `AI로 사진 꾸미기` 버튼과 그라디언트 영역 (`51:29`)
- AI 별 아이콘 (`52:171`, `63:371`)
- `AI가 소개글을 다듬어 드려요.` 안내
- `AI로 글 다듬기` 버튼 (`63:370`)

`AI로 사진 꾸미기` 버튼은 Figma `54:191`의 더미 모달 과정을 연다. 스타일 선택 → 생성 중 → 결과 비교까지만 로컬 상태로 진행하며 실제 AI 이미지 편집과 코인 차감은 없다. `AI로 글 다듬기` 버튼은 기본 → `다듬는 중...` → Figma `63:370`의 `원래대로` 상태로 전환한다. `원래대로`를 누르면 기본 버튼으로 복원하며 실제 문구 생성이나 입력값 변경은 없다.

## 3. DUMMY 정책

- 미리보기의 상품 이미지는 Figma 원본 정적 이미지 한 장을 로컬 에셋으로 저장해 사용한다.
- 업로드한 파일을 실제 Storage에 저장하지 않는다.
- 업로드 UI에서 파일을 선택하더라도 이번 단계에서는 정적 DUMMY 이미지로 미리보기를 구성한다.
- 완성 화면의 QR은 Figma 원본 DUMMY QR SVG를 사용한다.
- QR 생성 라이브러리, 공개 URL 생성, QR 다운로드, 클립보드 복사는 아직 연결하지 않는다.
- `QR코드 받기`, `주소 복사하기`는 디자인 확인용 버튼이며 실제 동작은 후속 승인 전까지 제공하지 않는다.

## 10. Vue 상태 구성

불필요한 컴포넌트를 늘리지 않고 `BuilderPage.vue` 안에서 관리한다.

```js
const currentStep = ref(1)

const form = reactive({
  name: '',
  price: '',
  weight: '',
  origin: '',
  feature: '',
  description: '',
  shopName: '',
  marketName: '',
  phone: '',
})
```

- 1, 2, 3, preview, complete 상태를 같은 페이지에서 조건부 렌더링한다.
- 각 입력 단계의 필수항목이 비어 있으면 필드 하단에 `필수항목입니다.`를 표시한다.
- 필수항목을 모두 입력하기 전에는 다음 버튼을 비활성화한다.
- 모든 필수항목 입력 후에만 다음 화면으로 전환한다.
- 서버 저장, 임시 저장, 새로고침 복구는 구현하지 않는다.
- 업로드 파일 URL 생성 여부는 후속 기능 범위이며, 이번 화면에서는 DUMMY 이미지로 고정한다.

## 11. 구현 전 확인사항

1. 2단계 제목을 Figma의 `상품사진과 주문전화`로 유지할지, 필드에 맞춰 `상품사진과 소개`로 수정할지
2. `다시 만들기`가 1단계로 돌아가기만 하는지, 입력값도 모두 초기화하는지
3. `발행하기` 클릭 시 바로 완성 화면으로 전환하면 되는지
4. DUMMY 버튼인 `QR코드 받기`, `주소 복사하기`는 클릭해도 아무 동작을 하지 않도록 둘지
5. 상품 사진 업로드 UI는 파일 선택만 허용하고 미리보기에는 고정 DUMMY 이미지를 유지할지
